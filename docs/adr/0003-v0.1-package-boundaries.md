# ADR-0003: Six physical packages for v0.1

**Status:** Accepted  
**Date:** 2026-08-11

## Context

The product architecture names many conceptual components but explicitly warns against over-fragmenting packages before boundaries are proven.

## Decision

Create six packages: `schemas`, `core`, `adapters`, `repo-map`, `benchmark`, and `cli`. Task Capsule, Compact Handoff, Context Budget, and metrics remain core modules rather than separate npm packages in v0.1.

## Consequences

- Fewer build/publication boundaries.
- Concepts remain independently testable through modules/interfaces.
- A component may become its own package later only when dependency or release pressure justifies it.
