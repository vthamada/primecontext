## Security and adversarial review outcomes

Independent read-only reviews reproduced and drove fixes for untrusted adapter
evidence, stale/mismatched snapshots, required-source truncation, Unicode
contract drift, false authority conflicts, ablation conflict recomputation,
ledger rehashing and chain anchoring, old-expansion retries, missing Git HEAD,
SQLite capability absence, FTS lock and two-file publication failure, CodeGraph
parser complexity, lexical shadowing, graph snapshot autocertification, secret
screening, path containment, state locks, and bounded errors.

The final read-only audit re-ran the high-risk reproductions and found no
material path to false `READY`, freshness bypass, path escape, sensitive-data
disclosure, corrupt-state acceptance, silent required-source omission, or an
unusable public command.

An attempted Codex Security workbench diff-scan launch could not seal its input
because concurrent implementation edits changed the selected working tree.
Following the scanner procedure, that launch was not retried in the same
response and produced no report artifact. The independent read-only adversarial
reviews and executable regressions above are the available evidence; this
record does not claim a completed workbench scan.

## Residual boundaries

- Secret/PII detection is conservative and bounded, not complete DLP.
- Repository content and excerpts remain untrusted data, never instructions.
- `.primecontext` is local, ignored, unencrypted state; protect it as repository
  data and use one writer per state directory.
- Link and file-snapshot checks retain a same-user TOCTOU window. Do not run
  elevated against an adversarial repository.
- The optional-adapter 30-second deadline is cooperative at bounded in-process
  checkpoints, not an operating-system CPU quota. Use process/container
  isolation for fully adversarial repositories.
- SQLite secure-delete controls do not erase filesystem snapshots, SSD history,
  backups, crash artifacts, or copies made outside PrimeContext.
- Atomic replacement and rollback cover the tested pre-publication failures,
  but there is no universal power-loss guarantee or directory `fsync`.
- Outcome receipts are declarations. Replay equality and experimental ablation
  do not establish causality, quality parity, or token savings.
- CodeGraph facts are bounded static observations, not proof of reachability,
  impact, safety, or authorization.
- The implementation is a verified local working tree. It is not committed,
  tagged, released, published, licensed, or benchmark-validated by this record.

## Conclusion

All 18 acceptance criteria for the specifically authorized v0.3 vertical slice
have direct executable evidence in this working tree, and the complete v0.1 and
v0.2 compatibility suite remains green. The implementation is usable locally
for its documented commands. Claims that it is revolutionary, state of the art,
causal, faster, cheaper, or more token-efficient remain deliberately unmade
until representative pre-registered benchmarks demonstrate quality parity and
the applicable human gates approve the wording.
