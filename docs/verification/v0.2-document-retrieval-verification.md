## Live checkout smoke

On 2026-08-12, the compiled CLI was exercised from the repository root after confirming that no `primecontext.config.json` or prior `.primecontext/documents` catalog existed. The smoke created only a temporary default config and `.primecontext/documents`, then ran:

```text
node packages/cli/dist/bin.js init
node packages/cli/dist/bin.js docs index
node packages/cli/dist/bin.js docs search "document retrieval" --limit 3 --authority specification --module specification --topic retrieval
```

Observed result:

- `docs index`: status 0, `.primecontext/documents/catalog.json`, 29 accepted documents, digest `sha256:27380a5c2c88f057b42e86479c234ad7c8c86b306478bdce39797f021f1d082d`;
- filtered search: status 0, one hit at `docs/specification/document-retrieval-specification-v0.2.md`, authority/module `specification`, topic `retrieval`, score 70, bounded six-line excerpt, no conflict group;
- the generated config and only the generated `.primecontext/documents` subtree were removed after their absolute paths and contents were checked; pre-existing `.primecontext` state was not removed.

The disposable integration test separately proves that a sensitive document is omitted and not returned. The live smoke used repository documentation only and is not a privacy review of an unrelated production repository.

A fresh pre-push diff review covered all 107 changed and supporting public surfaces. One low-severity disclosure issue in public verification prose was sanitized; exact private pilot and review evidence remains under ignored local state and outside Git. The complete 119-test suite then passed.

## Residual boundaries and human gates

- Content detection is conservative, not complete DLP; unrecognized secrets or confidential prose can still reach stdout.
- Search stdout includes the original query, normalized terms, metadata, and live excerpts. Captured output must be protected as repository data.
- Portable link checks retain a same-user TOCTOU window. Do not run elevated against an adversarial repository.
- Catalog replacement is single-writer. There is no directory `fsync`, universal power-loss rollback, or restoration after a successful rename followed by a later check failure.
- `.primecontext` is unencrypted local state. A custom `state_dir` must also be excluded from Git.
- At the time these commands were executed, the working tree was uncommitted, no package had been published, no remote had been changed, and no release/licensing gate had been crossed. Later Git transport does not retroactively make this record immutable release evidence.
