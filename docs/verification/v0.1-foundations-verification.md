## Scope decision

This checkpoint implements the v0.1 Foundations scope in the product specification and implementation architecture. It deliberately does not add the features deferred to later versions, including MCP, CodeGraph as a hard dependency, document retrieval, embeddings, vector databases, hosted services, a web UI, automatic multi-agent orchestration, or adaptive memory.

The public-release license and final public name remain explicit human decisions. Their deferral is recorded in [ADR-0007](../adr/0007-defer-public-license-selection.md) and does not weaken the implemented v0.1 runtime boundary.

## Implemented changes and corrected gaps

- Added deterministic physical JSON contracts for all six public v0.1 data structures, package subpath exports, generation/parity checks, and strict configuration validation.
- Aligned schema and runtime validation for safe integers, JSON-safe metadata, bounded nesting, estimate labels, unique repo-map IDs, module counts, completion evidence, and portable task IDs.
- Made budget defaults immutable, derived the hard limit from the effective soft limit, and returned defensive copies from Core boundaries.
- Added repository-contained, link-aware, bounded CLI input/output handling and strict command-line parsing with stable PrimeContext error classes.
- Hardened filesystem discovery and reads against traversal, symlinks, junctions, Windows aliases, alternate data streams, device names, sensitive paths, excessive depth, excessive entries, and excessive excludes.
- Changed Git inspection to a shell-free, read-only, fail-open process with time and output limits.
- Added validated JSONL metric recording, bounded aggregation, safe overflow handling, strict A/B identity checks, raw deltas, completion evidence, and conservative quality interpretation.
- Made repo-map ordering ordinal and deterministic, added distribution allowlists, generated a lockfile, and excluded tests/source build state from package tarballs.
- Added complete CLI, benchmark, security, roadmap, governance, contract, pilot, and release-decision documentation.

The audit reproduced and corrected concrete failures in task-path traversal, intermediate-link escape, secret-name coverage, Windows path aliases, unbounded structured inputs, unsafe numeric aggregation, metadata accessor execution, schema/runtime drift, malformed CLI arguments, misleading benchmark comparability, native I/O classification, terminal-control output, and package contents. Each behavioral correction is covered by a regression test.

Architecturally, Core remains vendor- and I/O-agnostic; structured external validation and repository containment stay at ingress; schemas remain the dependency root; MaxSound data remains outside Core; and concepts deferred to v0.2 remain modules or roadmap items instead of premature packages.

## Security review

A private standard security review of a pre-remediation snapshot found path/link, input-validation, disclosure, resource-bound, and terminal-output control gaps. Correlatable scan identifiers, digests, and raw evidence remain outside Git. The working tree subsequently added regressions and remediations covering:

- repository containment and every existing path component, including links and junctions;
- portable safe task IDs before any task-derived path access;
- sensitive names, cloud credentials, keys/certificates, Windows aliases, alternate data streams, device names, and trailing dot/space aliases;
- bounded file sizes, JSON depth/value counts, repository discovery, exclude count, and metric aggregation;
- sanitized error messages with structured raw details retained for programmatic consumers;
- shell-free, read-only, time- and buffer-bounded Git inspection.

The private canonical report remains evidence only for its original snapshot. Current-tree conclusions require the fresh verification recorded for the eventual immutable commit.

Residual risks are documented in [Security and residual risks](../security-and-residual-risks-v0.1.md). In particular, portable path checks cannot eliminate a same-user link-swap race between validation and opening, allowed source files are not content-scanned, local state is not encrypted, semantic inference is intentionally shallow, and metric inputs remain self-reported.

## Delivery and release gates

The v0.1 implementation is complete at this checkpoint. At the time of this verification it had not yet been staged, committed, pushed, published, or deployed. Later Git transport does not retroactively change this point-in-time evidence and does not constitute a package or public release.

Public release is a separate gate and remains blocked on decisions that the approved specification intentionally leaves to people:

- select the license after legal/public-release review;
- freeze the public product name;
- confirm the private security-report contact;
- review the final staged scope and create the release commit/remote publication.

No production-performance or token-savings claim is approved by the evidence in this record.
