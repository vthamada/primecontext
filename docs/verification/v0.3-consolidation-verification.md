## Migration, rollback, and residual boundaries

- v0.1/v0.2 contracts and commands remain compatible; new contract fields are
  additive and documented legacy paths remain validator-compatible.
- Index replacement is a full screened sibling rebuild. A failed manifest
  publication restores the prior validated database/manifest pair where the
  documented filesystem primitives succeed.
- Chained ledgers detect replacement, removal, reordering, stale-plan retry,
  and duplicate outcomes; a validated legacy prefix is accepted only before
  the first chained record.
- A positively stale lock remains fail-closed and requires exact manual
  removal after the operator independently confirms that no writer exists.
- Initialization never replaces an existing configuration. Its create-only
  hard-link publication is flushed first and remains fail-closed/retryable when
  another writer wins or configuration/ignore state changes.
- Adapter timeouts are cooperatively enforced, not OS-level CPU/memory kills.
- Security-task applicability is a bounded conservative lexical classifier,
  not semantic comprehension. Core and CLI projections are separately
  implemented and protected by a direct 44-case parity regression.
- POSIX modes request private state permissions. Windows ACL hardening is not
  implemented or claimed.
- Secret screening is conservative and bounded, not complete DLP. A residual
  TOCTOU window remains between the last stable reread and atomic publication.
- Receipts are linked auditable records; they are not self-contained proofs of
  semantic correctness or every omitted body.
- SQLite/FTS and the internal TypeScript graph remain optional. Their absence
  preserves the complete safe filesystem/document fallback.
