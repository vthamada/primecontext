# PrimeContext v0.1 Foundations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the smallest end-to-end PrimeContext v0.1 implementation that safely maps a repository, allocates a context budget, generates/validates a Task Capsule, validates Compact Handoffs, and records benchmark-ready metrics.

**Architecture:** Six-package TypeScript/npm-workspaces monorepo. JSON Schema validation guards external boundaries; core remains adapter-agnostic; Node filesystem/Git adapters feed a deterministic semantic repo map; CLI composes the packages. Generated runtime state is JSON/JSONL under `.primecontext/`.

**Tech Stack:** Node.js 22.13+, TypeScript strict/ESM, npm workspaces, Node `node:test`, JSON Schema-compatible contracts, JSON/JSONL state.

## Global Constraints

- Local-first; no mandatory cloud or paid service.
- Agent-agnostic and adapter-based.
- No MaxSound business rules in Core.
- No CodeGraph, MCP, embeddings, vector DB, SaaS, web UI, or automatic orchestration in v0.1.
- Secrets must be excluded before reads.
- Optional integrations fail open.
- No token-savings claim without A/B evidence and quality guardrails.
- Context budgets remain configurable experimental defaults.
